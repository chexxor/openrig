# Peer review (independent, then compare)

Where two seats share a role, they exist to **catch each other's errors**, not
to agree.

- **Review independently first.** Do not read the other reviewer's notes
  before forming your own — independence is what makes disagreement
  informative.
- Report: what you checked, the evidence, and a verdict
  (`pass` / `pass-with-notes` / `fail`).
- When reviewers disagree, the **disagreement is the signal**: the lead
  synthesizes it; neither side silently defers.
- For paired implementers: cross-review each other's diffs — read the actual
  change, run the test, and say what you would have done differently.
